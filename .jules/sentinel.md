## 2024-05-18 - Client-Side Password Verification Bypass
**Vulnerability:** The settings popup (`src/components/SettingsPopup.jsx`) verified the current password on the client side by comparing the plain text input against `currentUser.password_hash` exposed by the backend to the frontend.
**Learning:** `password_hash` being exposed to the client in the current user session is dangerous and enables client-side verification bypass, meaning any client can change a user's password if they have access to the UI and know the `password_hash`. Because of this, it can also lead to horizontal and vertical privilege escalation if users are able to access other user's hashes via an API endpoint.
**Prevention:** Always verify passwords securely on the backend. Do not expose `password_hash` in the `currentUser` object on the frontend. While the backend change is outside the scope of this fix, the immediate mitigation is to use the `login` API call for verification before proceeding with password update.
